# With Payload's plugins

payload-onpage writes through Payload's REST API and its hooks, so Payload's own plugins keep working. This page covers what to set for each one.

## SEO (`@payloadcms/plugin-seo`)

The `meta` group (title, description, image) renders in `<head>`, not on the page, so there's nothing to click. Editors change it in the admin.

In edit mode `meta.title` and `meta.description` are text, so they carry markers into `generateMetadata`. Leave them unmarked:

```ts
onpage({
  collections: ['pages'],
  session: nextSession(),
  encode: ({ path }) => !path.startsWith('meta.'),
})
```

or strip markers where you build metadata (`stegaCleanDeep(doc)`, from `@payload-onpage/core`).

## Nested docs (`@payloadcms/plugin-nested-docs`)

A nested page lives at its breadcrumb URL (`/parent/child`), not at `/<slug>`. Tell the plugin:

```ts
onpage({
  collections: {
    pages: {
      url: ({ doc }) => {
        const crumbs = doc.breadcrumbs as Array<{ url?: string }> | undefined
        return crumbs?.at(-1)?.url ?? `/${String(doc.slug)}`
      },
    },
  },
  session: nextSession(),
  // Breadcrumbs are generated by the plugin's hook: don't offer them for editing.
  encode: ({ path }) => !path.startsWith('breadcrumbs'),
})
```

## Redirects (`@payloadcms/plugin-redirects`)

`slug` isn't marked (it's a machine name), so it isn't edited on the page. When you change a slug in the admin, add a redirect from the old path there too.

## Search (`@payloadcms/plugin-search`)

The search index syncs on save. With `syncDrafts` off (its default), on-page autosaves don't touch the index; publishing does.

## Form builder (`@payloadcms/plugin-form-builder`)

A form block points at a document in the `forms` collection. Its labels come from that document, which isn't enabled for on-page editing, so they aren't clickable; edit the form in the admin. The form still works while editing, and its submissions are real.

## Multi-tenant (`@payloadcms/plugin-multi-tenant`)

Access rules from the tenant plugin apply as they do in the admin.

The editor opens pages on the admin's own origin (`serverURL`). For tenants on their own domains, serve the admin on each tenant's domain and leave `serverURL` unset, or keep tenants on paths of one domain. A `url` that points at another origin resolves to no page.

## Storage adapters (S3, Vercel Blob, R2, …)

Uploads from the image editor go through Payload (`POST /api/<collection>`), so the adapter stores them as usual. On Vercel, a server function accepts at most 4.5 MB per request, so larger images fail there. Payload's `clientUploads` option covers only the admin. For large files on the page, pass a [custom media library](custom-media-library.md) that uploads to your storage directly.
